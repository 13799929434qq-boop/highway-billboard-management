# 项目文档与项目说明

这是面向公路沿线广告牌经营管理单位的业务系统，用于统一管理路段、广告牌、客户、合同、收款和报表，逐步替代分散的 Excel 台账和纸质合同。

## 唯一需求基线

产品范围、页面分组、功能点、优先级、TAPD 需求 ID 和开发批次，统一以 [`需求基线_TAPD对齐版_V1.0.md`](requirements-需求文档/需求基线_TAPD对齐版_V1.0.md) 为准。

- TAPD 工作区：魔幻陀螺组（ID `64099159`）。
- 当前基线包含 P0 全局与工作台，以及 P1～P8 八个业务页面组；共记录 54 个 TAPD 需求 ID，具体功能数量和编号以基线正文为准。
- 与基线冲突的旧清单、旧交付件和旧设计不得作为开发或验收依据；需要时从 Git 历史追溯。
- 关键验收闭环：登记广告牌 → 签订多广告牌合同 → 按年度形成应收 → 登记收款并核销 → 查看经营报表。

## 开发批次

| 批次 | 内容 | 交付物 |
|---|---|---|
| 第一批（前置） | P1 登录、权限、数据字典、操作日志 | 能登录、能配置权限、操作可追溯 |
| 第一批（并行） | P6 报表界面（模拟数据） | 报表、筛选和导出可演示 |
| 第二批 | P2 广告牌建档 | 路段、广告牌、证件和照片 |
| 第三批 | P3 客户 + P4 合同 | 客户档案、多广告牌合同和年度价格 |
| 第四批 | P5 财务 | 应收、收款、挂账和核销 |
| 第五批 | P8 售后 + P7 提醒 + 报表真实数据 | 售后闭环、提醒和数据对账 |

## 推荐阅读顺序

1. 先读需求基线，确认范围、优先级和 TAPD ID。
2. 再读领域上下文，统一业务术语。
3. 涉及架构或技术实现时，读取架构决策和技术架构。
4. 涉及界面时，读取产品设计目录中的现行设计。
5. 开发方法类文档只作辅助，不得用来新增需求。

## 目录边界

- 根目录 `AGENTS.md` 是开发代理自动发现的控制文件，必须保留在项目根目录。
- 根目录 `openspec/` 保存已暂停的 OpenSpec 配置和历史变更，不是当前任务管理流程。
- `.agents/`、`.artifact-work/`、依赖、缓存、截图和临时生成文件不属于正式项目文档。
