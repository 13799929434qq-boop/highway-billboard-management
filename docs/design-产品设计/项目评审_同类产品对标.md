# 高速公路广告牌管理系统：同类产品对标与项目评审

> 状态：暂停。该文档仅保留为产品定位背景，不作为当前功能范围或开发依据。当前评审以《项目评审_现行功能范围.md》为准。

评审日期：2026-10-07  
评审范围：现行 TAPD 对齐需求基线 V1.0、当前 UX 布局方案  
评审目的：确认产品定位，判断它与“广告招标平台”和“广告牌经营管理系统”的匹配程度。

## 一、先给结论

当前项目是一套**高速公路广告牌经营管理后台**，核心是广告牌建档、客户、合同、应收收款、报表、提醒和维护。

它不是一套完整的**广告经营权在线招投标平台**。现行 PRD 没有招标公告、投标人报名、资格审查、投标文件递交、开标、评标、中标公示和保证金等流程。

因此：

- 如果项目名称和验收目标是“广告牌经营管理系统”，当前产品方向成立。
- 如果答辩或甲方要求的是“广告招标平台”，当前产品定位与功能范围存在明显缺口，需要先做需求变更，不能只通过修改页面解决。

## 二、参考产品与可借鉴内容

### 1. 公共资源交易平台：参考招投标过程

参考案例：益阳市中心城区户外广告经营权项目。公开招标文件包含投标资格、招标公告、电子投标、评审与结果等环节。

参考地址：

- https://jyzx.yiyang.gov.cn/TPFrame/AttachStorage2/202507/PDF/dff7894f-5567-451f-91bb-f0fd3875bb53/9f55c744-355e-4898-b59c-0684868cb444.pdf
- https://ggzyfw.beijing.gov.cn/ （全国各地公共资源交易产品可作为信息架构参考）

可借鉴的页面结构：

1. 项目公告列表：项目名称、标段、报名时间、开标时间、当前状态。
2. 项目详情：标的物、资格条件、文件下载、时间节点、联系方式。
3. 投标过程：报名、资格材料、投标文件、保证金、递交状态。
4. 评审过程：开标记录、评审结果、中标候选人、公示与异议。

这些流程目前不属于现行 PRD，只用于判断“是否属于招标平台”。

### 2. Broadsign Platform：参考户外广告资源经营

Broadsign 面向户外广告媒体所有者和购买方，覆盖广告资源、可用档期、销售、广告活动和报表。它将数字屏和静态广告面统一为库存，并按照用户权限提供不同模块。

参考地址：

- https://broadsign.com/broadsign-platform/
- https://docs.broadsign.com/broadsign-platform/en/introduction.html
- https://docs.broadsign.com/broadsign-direct/introduction.html

适合当前项目借鉴的部分：

1. 广告资源先成为统一库存，再进入销售或合同流程。
2. 资源列表突出位置、规格、状态与可用时间。
3. 预订时实时检查档期，防止重复占用。
4. 角色进入系统后直接看到与本职工作相关的模块。
5. 资产、销售、执行与报表保持同一事实来源。

当前项目已经覆盖其中的资产档案、租期冲突检查、合同、财务和报表，方向较一致。

### 3. AdQuick for Media Owners：参考库存与经营视角

AdQuick 面向户外广告媒体经营者，强调广告资源库存、档期占用、维护、租赁、账单、收入和利用率。

参考地址：

- https://www.adquick.com/media-owners

适合当前项目借鉴的部分：

1. 资源是否空闲、何时被占用是列表和详情的重要信息。
2. 销售、合同、维护和财务围绕同一块广告资源关联。
3. 经营报表应能回答利用率、收入、空闲资源和即将结束的租期。

## 五、当前 UI/UX 应该参考什么

当前系统的页面设计应主要参考 **Broadsign/AdQuick 一类资源经营后台**，而不是照搬公共资源交易门户。

- 内部工作人员使用的资产、合同、财务页面：采用稳定侧边导航、筛选、数据表格、快速详情和正式详情。
- 如果未来新增对外招标：另外设计公开门户、项目详情和投标人工作台，不应把它们塞入现有内部管理后台。
- 六类内部岗位共用同一套设计系统，根据菜单、数据和按钮权限呈现不同内容。

## 六、评审结论

当前 UX 布局方向与“广告牌经营管理后台”匹配，可以继续设计客户、合同、财务和报表模块。

项目下一步最重要的产品决策不是圆角或配色，而是统一对外定位：

> 高速公路广告牌经营管理系统，用于管理广告牌资产、客户合同、收费收款、经营报表和维护业务。

在需求没有正式变更前，不应宣传为“广告招标平台”，也不应擅自加入在线招投标功能。
