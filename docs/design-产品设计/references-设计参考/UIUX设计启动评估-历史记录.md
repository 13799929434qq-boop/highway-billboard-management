## 四、六阶段计划校准

| 阶段 | 原计划 | 校准建议 |
|---|---|---|
| P1 UX 与信息架构 | 1–2 天 | 保留；图表用 Mermaid/HTML 替代 FigJam |
| P2 低保真 | 3–4 天 | 保留；交付 **HTML 线框**（浏览器可看、可点） |
| P3 视觉风格探索 | 3 方向 5–6 天 | **收窄**：先评审旧 DESIGN.md（暖色企业风）决定继承/微调，至多再出 1 个备选，不做 3 个从零方案 |
| P4 设计系统与高保真 | 7–10 天 | 保留；以 DESIGN.md + HTML 高保真交付，Figma 组件库视 D1 |
| P5 交互原型与 UX 验收 | 11–12 天 | 以**可点击 HTML 原型**连接页面（不拿静态图冒充）；Figma Prototype 视 D1 |
| P6 设计交付与开发衔接 | 13–14 天 | 保留；输出页面↔TAPD 映射与前端交付清单 |

**闸门机制不变**：Plan → Execute → Review → Approve → Next；每阶段暂停，不连续自动执行。

## 五、Phase 1 详细执行内容（待批准）

**任务：**
1. **角色×场景矩阵**：6 角色的目标、高频任务、主要入口、权限边界；
2. **MVP 页面清单**：按 P1~P8 列出全部页面，每页标注：页面名、关联 TAPD ID、页面类型（登录/列表/表单/详情/看板/报表）、数据来源；
3. **信息架构与导航树**：一级/二级导航对齐 8 大类；明确"工作台、审批待办、AI 助手"去留；
4. **核心用户流程（含跨角色泳道）**：登录、广告牌建档、客户登记、签约（多牌）、按年收款/核销、报表查看、提醒、售后处理；
5. **页面跳转关系图**：入口、动作、目标页与异常分支。

**交付物：**
- `docs/design-产品设计/documents-现行设计文档/信息架构-现行版.md`（导航树 + 页面分层 + Mermaid 结构图）
- `docs/design-产品设计/documents-现行设计文档/用户流程-现行版.md`（泳道流程 + 跳转关系）
- `docs/design-产品设计/documents-现行设计文档/MVP页面清单-现行版.md`（页面↔TAPD 映射表）

**验收条件：**
- 每个核心页面可追溯到 TAPD 需求，无凭空页面；
- 导航层级清晰、角色入口正确；
- 主要业务流程端到端走通、无断链；
- 与当前 8 大类基线一致。

**完成后立即暂停**，提交审核，不进入 Phase 2。

## 六、需你确认的两点

1. 交付形态：是否同意以 **可点击 HTML 原型 + Markdown 规格** 为主（Figma 仅出提示词）？还是你能提供 Figma 环境/Token？
2. 信息架构："工作台（首页）"是否纳入本期（建议纳入为登录后默认页，聚合待办与指标）；"审批待办、AI 助手"建议列后续，是否认可？
