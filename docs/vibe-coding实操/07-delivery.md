# Phase 7 产品落地与交付

> 将可运行原型变成可验收、可部署、可迁移和可持续维护的产品

## 交付目标

产品落地不是把代码部署到服务器，而是让客户能够在受控数据、权限和运维条件下完成真实业务。正式客户数据进入系统前，必须完成阿里云正式环境、权限矩阵、数据迁移、备份恢复和安全检查。

## 一 交付物

| 类别 | 交付内容 |
|---|---|
| 产品 | PRD、完整需求规格、产品设计、页面清单和原型 |
| 业务 | 统一术语、领域模型、关键流程、状态机和业务规则 |
| 技术 | 架构设计、ADR、OpenAPI、数据库迁移和交互式架构图 |
| 测试 | Eval 基线、测试与验收方案、固定测试数据和自动化结果 |
| 代码 | 前端、后端、后台任务、基础设施配置和构建脚本 |
| 运维 | 环境变量清单、部署手册、监控告警、备份恢复和故障预案 |
| 数据 | 数据字典、迁移模板、校验报告和回滚方案 |
| 培训 | 角色操作手册、管理员手册和常见问题 |

## 二 分阶段部署

### 个人开发与试用

- Vue Vite 前端部署到 Vercel。
- FastAPI 使用 Vercel Python Runtime 或独立测试服务。
- 仅使用测试、虚构或脱敏数据。
- 保留 Dockerfile 和云资源适配层，避免与 Vercel 绑定。
- 每个分支生成预览环境，支持产品和设计快速验收。

### 正式生产

```text
用户
  → 阿里云 CDN 与 OSS 前端
  → 负载入口
  → ECS Docker FastAPI 与后台任务
  → RDS MySQL Redis OSS Milvus
```

- 云资源部署在选定地域和同一 VPC。
- 数据库、Redis、Milvus 不暴露公网。
- OSS 使用私有 Bucket、生命周期和版本策略。
- 密钥通过环境变量或密钥管理服务注入。
- 正式域名启用 HTTPS、安全头、访问日志和必要的 WAF 策略。

## 三 发布前检查

### 业务

- 客户确认点位、广告面、客户、合同、应收和收款迁移口径。
- 明确临期天数、逾期升级、巡检周期和风险等级规则。
- 确认制单人与确认人的职责分离。
- 以真实但脱敏的代表性场景完成 UAT。

### 数据

- 完成源数据盘点、字段映射、清洗、重复识别和缺失处理。
- 迁移前后核对记录数、合同金额、应收余额、收款余额和核销余额。
- 为无法自动映射的数据生成待人工确认清单。
- 迁移脚本可重复运行并有明确回滚策略。

### 安全

- 页面、接口、导出、附件和 AI 完成权限隔离测试。
- API Key、数据库密码、云凭据和会话密钥不在 Git 和日志中。
- 文件下载使用受控授权。
- 真实合同和财务数据不经过未经批准的模型或测试环境。
- 审计日志覆盖合同确认、核销、退款、作废、导出和权限变更。

### 质量

- 所有发布阻断用例通过。
- 数据库迁移在生产副本上演练成功。
- 核心页面在 1366×768、1440×900 和关键移动断点通过。
- AI、Redis、Milvus 和 OSS 故障演练符合降级预期。
- 备份恢复演练在目标恢复时间内完成。

## 四 CI CD 流程

```text
Pull Request
  → 格式检查与类型检查
  → 单元和接口测试
  → 前端构建与后端镜像构建
  → 依赖和安全扫描
  → 预览环境
  → 人工验收
  → 正式部署
  → 数据迁移
  → 冒烟测试
  → 监控观察
```

数据库迁移与应用发布分步执行。破坏性结构变更采用扩展、回填、切换、清理的渐进方式，不在一次发布中直接删除仍被旧版本使用的字段。

## 五 上线步骤

1. 冻结正式迁移数据的变更窗口。
2. 备份源数据和目标数据库。
3. 部署兼容旧数据结构的应用版本。
4. 执行 Alembic 迁移和数据导入。
5. 运行自动校验与财务余额核对。
6. 业务负责人抽查合同、应收、收款和资源占用。
7. 切换域名或流量。
8. 执行登录、合同查询、收款查询、权限和 AI 降级冒烟测试。
9. 观察错误率、延迟、连接池、任务失败和关键业务指标。
10. 解除变更窗口并发布上线通知。

## 六 验收场景

| ID | 场景 | 验收结果 |
|---|---|---|
| AT-01 | 建立点位与多个广告面 | 层级和状态正确 |
| AT-02 | 创建并确认合同 | 占用租期并按收费计划生成应收 |
| AT-03 | 重叠租期合同 | 被准确阻止并显示冲突依据 |
| AT-04 | 分期收款和一收多核 | 所有余额和状态正确 |
| AT-05 | 待认领收款转客户挂账 | 全过程可追溯 |
| AT-06 | 合同变更与应收调整 | 原记录保留，报表口径正确 |
| AT-07 | 退款和作废 | 影响范围清楚，记录不可删除 |
| AT-08 | 巡检缺陷到维修验收 | 状态闭环和附件完整 |
| AT-09 | 权限隔离 | 页面、接口、导出和 AI 均拒绝跨范围访问 |
| AT-10 | AI 合同录入 | 字段带来源，只生成待确认草稿 |
| AT-11 | 风险摘要 | 规则命中正确，AI 解释带业务来源 |
| AT-12 | 依赖故障 | AI 或检索不可用时核心业务继续运行 |

## 七 监控和运营

- 技术指标：请求量、错误率、P95 延迟、数据库连接、缓存命中、任务失败、模型耗时和 token。
- 业务指标：资源经营率、合同确认时长、应收逾期、回款率、待认领余额、缺陷闭环时间。
- 数据质量：合同金额与收费计划不一致、无应收的已确认合同、负余额、孤立附件和权限异常。
- AI 质量：字段采纳率、人工修改率、引用打开率、无依据拒答率、模型错误率和单任务成本。

告警必须包含环境、追踪编号、影响模块、开始时间和处理入口。不得在告警正文中暴露合同全文、个人信息或密钥。

## 八 回滚与恢复

- 应用版本支持快速回滚到上一个稳定镜像。
- 数据库变更优先向前修复；确需回滚时使用已验证脚本和备份。
- 发布后发现财务余额异常时立即停止相关写操作，不直接手工改库。
- AI 索引按版本切换，可回退到上一完整索引。
- OSS 文件启用适当版本或保留策略，避免误删不可恢复。

## 九 后续迭代

### 第一优先级

- 完成资源、客户、合同、应收、收款和核销的 P0 闭环。
- 固化权限、审计、幂等和并发控制。
- 建立经营工作台和关键风险下钻。

### 第二优先级

- 上线巡检维修闭环、报表导出和规则配置。
- 上线 AI 合同录入、文档问答和风险摘要。
- 用真实脱敏样本持续维护 AI Eval 数据集。

### 第三优先级

- 优化路线经营分析、移动巡检和管理层报告。
- 根据真实使用数据优化流程、索引、缓存和模型成本。
- 在不破坏业务边界的前提下扩展更多 AI 建议场景。

## 十 交付完成定义

- 客户可用授权账号完成约定的端到端业务流程。
- 关键余额、租期和状态可复核并可追溯。
- 权限、审计、安全、备份和降级通过验收。
- 文档、代码、迁移、测试与实际部署版本一致。
- 未决事项、已知限制、责任人和计划日期均有记录。
