# Phase 2 功能规划文档

> 将需求对话转化为可开发、可测试、可追溯的产品规格

## 产品定义

高速公路广告牌经营管理系统用于统一管理广告资源、客户合同、应收实收、巡检维护和经营分析。系统以正式业务记录为事实来源，通过 AI 提高合同录入、资料检索和经营解释效率，但所有正式变更必须经过确定性规则和有权限用户确认。

## 不可破坏的业务规则

1. 广告面是最小可出租资源。
2. 合同确认后才占用租赁时段并生成正式应收。
3. 双人确认场景中，制单人与确认人不能相同。
4. 收款流水不因尚未核销而失效。
5. 核销金额不得超过收款可用余额或应收未结余额。
6. 已确认合同、应收、收款、核销和退款不得物理删除。
7. 历史错误通过变更、调整、退款或作废纠正。
8. AI 输出不是正式业务事实，必须经过规则校验和人工确认。
9. AI 和导出不得超出当前用户权限与数据范围。

## 技术架构

```text
Vue 3 SPA
  │ HTTPS JSON Multipart SSE
FastAPI 模块化单体
  ├─ 身份权限与数据范围
  ├─ 资源 客户 合同 财务 巡检 分析
  ├─ AI 应用与模型网关
  └─ 后台任务与审计
       ├─ MySQL 8 正式业务事实
       ├─ Redis 缓存 锁 队列状态
       ├─ OSS 私有文件
       └─ Milvus 向量检索
```

## 完成标准

- 每个 P0 功能都有明确输入、输出、状态、权限、错误和审计要求。
- API 写操作定义幂等策略和并发保护。
- 数据模型能从任意余额追溯到原始业务记录。
- AI 功能明确来源、权限、人工确认和降级路径。
- 页面功能和后端接口使用统一领域术语。
