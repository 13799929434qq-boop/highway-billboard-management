# 测试、联调与交付清单（参考）

状态：**参考资料**。具体测试范围以本次 TAPD 需求和验收标准为准；未进入当前需求的 AI、Milvus、OSS 等能力不纳入默认交付。

## 测试设计

每个需求至少覆盖：

- 正常流程：验收标准中的主路径可以完成。
- 边界条件：空值、临界日期、最大长度、金额精度和重复操作。
- 权限与数据范围：页面、接口、导出和附件不能跨范围访问。
- 失败处理：写入失败时事务完整回滚，不留下部分成功状态。
- 历史追溯：正式记录的变更、作废或修正保留原因、操作人和前后差异。

高风险业务应额外验证：

- 同一广告牌的重叠租期被阻止，相邻租期按统一日期规则判断。
- 合同生效后，相关广告牌租期和年度应收结果一致。
- 重复请求不重复生成应收、收款、核销或其他正式记录。
- 核销不得超过收款可用余额或应收未结余额，并发请求不能造成负余额。
- 无权访问时不通过错误差异泄漏对象是否存在。

## 前后端联调

1. 后端接口与前端类型在日期、金额、枚举、分页和错误码上保持一致。
2. 模拟数据集中管理，不散落在页面组件中。
3. 所有错误响应包含可关联的追踪信息，用户提示不暴露内部异常或敏感数据。
4. 合同、应收、收款和核销变化后，详情、列表、报表和审计显示一致。
5. 文件、缓存、AI 或其他可选依赖发生故障时，按已批准架构执行降级；没有批准的依赖不应被默认接入。

## 推荐联调顺序

联调顺序跟随需求基线的开发批次：

1. P1 登录、权限、数据字典和操作日志。
2. P6 报表界面与模拟数据。
3. P2 广告牌资产。
4. P3 客户和 P4 合同。
5. P5 应收、收款、挂账和核销。
6. P7 提醒、P8 售后以及报表真实数据。

## 发布前检查

### 业务与数据

- 本次 TAPD 验收标准全部有对应测试或人工验收记录。
- 数据迁移前后核对记录数、合同金额、应收余额、收款余额和核销余额。
- 无法自动处理的数据进入明确的人工确认清单。
- 需求未明确的规则不通过代码默认值偷偷决定。

### 安全与质量

- 页面、接口、导出和附件完成权限隔离检查。
- 密钥、数据库密码、访问令牌和真实合同正文不进入 Git 或普通日志。
- 数据库迁移、备份恢复和失败回滚已经验证。
- 前端类型检查、构建以及相关自动化测试通过。
- 后端相关测试和健康检查通过。

### 上线与观察

- 记录应用版本、数据库迁移版本、环境变量变化和回滚方式。
- 上线后执行登录、权限、核心查询和本次改动主流程的冒烟测试。
- 观察错误率、响应时间、数据库连接和关键任务失败情况。
- 发现金额、权限或数据一致性问题时停止相关写操作，不直接手工修改正式数据库。

## 交付完成标准

- 用户可以使用授权账号完成约定业务流程。
- 验收结果能够追溯到 TAPD ID 和对应测试。
- 关键金额、租期、状态和历史记录可以复核。
- 文档、代码、迁移和实际部署版本一致。
- 未决事项、已知限制、负责人和后续计划已经记录。
