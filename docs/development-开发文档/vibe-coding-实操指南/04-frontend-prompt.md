# Phase 4 前端开发提示词

> 可直接交给 Codex 或其他前端编码代理的实施任务

## 主提示词

你是一名资深企业级前端工程师和产品设计工程师。请实现“高速公路广告牌经营管理系统”的 Vue 3 Web 前端。先读取项目中的 `docs/domain-领域模型/CONTEXT-领域上下文.md`、`docs/design-产品设计/04-界面设计规范.md`、`docs/development-开发文档/vibe-coding-实操指南/02-feature-spec.md` 和 `docs/development-开发文档/vibe-coding-实操指南/03-eval-baseline.md`，以其中的业务术语、AI 边界和验收标准为准。不要把文档中的示例数据当作生产事实。

## 技术栈

- Vue 3、Vite、TypeScript
- Vue Router、Pinia
- Element Plus
- Axios 或项目既有请求封装
- TanStack Query 管理服务端状态
- Zod 校验接口数据
- ECharts 绘制经营趋势和结构图
- Vitest、Vue Test Utils、Playwright

## 设计方向

- 企业经营后台，不是宣传网站。
- 使用暖米色画布 `#FAF9F5`、白色工作表面、深墨色文字 `#141413`。
- 珊瑚色 `#CC785C` 仅用于主操作、选中状态和少量重点。
- 深色侧栏和 AI 区域使用 `#181715`，同屏最多一个大面积深色区。
- 以对齐、分组、留白和细分隔线建立层级，减少阴影和装饰卡片。
- 状态必须同时使用文字或图标，不能只依靠颜色。
- 避免紫色渐变、玻璃拟态、营销式大标题和无业务意义的 Bento 卡片。

## 应用框架

实现可折叠左侧导航和 64px 顶栏。一级导航包括：

1. 经营工作台
2. 广告牌资产
3. 客户管理
4. 合同管理
5. 财务与回款
6. 巡检维护
7. 经营分析
8. AI 经营助手
9. 系统管理

顶栏包含面包屑、全局搜索、待办入口、AI 入口和用户菜单。页面顶部显示当前统计周期、组织、路线、区域、责任人、数据更新时间和权限范围。

## 首批页面

### 1 登录与权限反馈

- 登录、会话过期、无权限和账号停用状态。
- 不在前端存储长期敏感令牌。

### 2 经营工作台

- 经营指标组合摘要，不堆叠一排相同卡片。
- 今日优先事项，展示风险等级、业务对象、事实、影响、责任人、持续时间和操作入口。
- 合同额、计划应收和实际回款趋势。
- 广告资源状态与路线经营表现。
- 巡检维修概况。
- 克制的 AI 经营摘要入口，清楚区分系统事实与 AI 建议。

### 3 广告资源

- 点位和广告面列表、详情、地图或路线视图。
- 筛选经营状态、路线、区域、合规状态。
- 广告面详情展示租期占用时间线和关联合同。

### 4 合同管理

- 合同列表、详情、创建编辑、规则校验、确认、变更和作废。
- 长表单按基本信息、广告面与租期、收费计划、附件、特殊约定和确认摘要分段。
- 提交确认前显示资源冲突、金额差异、缺失附件等校验结果。
- 合同确认页展示制单人、确认人、前后差异和影响范围。

### 5 财务与回款

- 应收账单、收款流水、待认领收款、客户挂账、核销和退款。
- 金额右对齐并使用等宽数字。
- 核销界面实时展示收款可用余额、应收未结余额和分配合计。
- 高风险操作显示对象、影响范围和不可逆后果，等待服务端确认。

### 6 AI 经营助手

- 对话历史、输入区、事实、建议、来源、模型、生成时间和权限范围。
- 合同提取任务显示排队、处理中、待确认、完成和失败状态。
- AI 生成字段必须带“待确认”标识、来源片段和置信提示。
- 不提供绕过正常合同确认、核销或审批的直接执行按钮。

## 通用组件

- `AppShell`、`SideNav`、`TopBar`、`PageHeader`
- `FilterBar`、`SavedViewSelector`
- `MetricSummary`、`RiskQueue`、`StatusTag`
- `DataTable`、`DetailDrawer`、`AuditTimeline`
- `MoneyInput`、`DateRangeField`、`ChargePlanEditor`

- `AiAnswer`、`AiSourceList`、`AiSuggestion`、`AiTaskStatus`

## 接口和状态要求

- 使用统一 API Client，自动附加追踪编号和会话凭证。
- 为分页、筛选、排序和缓存键建立稳定类型。
- 写操作处理重复提交、幂等响应、字段级错误和全局错误。
- 网络失败时保留未提交输入并提供重试。
- 列表区分暂无数据、筛选无结果和无权查看。
- 长任务允许离开页面，之后从任务中心恢复查看。
- AI 不可用时回退到规则摘要和普通业务页面。

## 响应式和可访问性

- `>=1200px` 使用完整侧栏和多栏布局。
- `768–1199px` 收起侧栏，双栏表单改为单栏，地图与明细可进入独立页面。
- `<768px` 只保留经营摘要、紧急待办、审批和拍照上传等高频任务。
- 所有交互支持键盘，焦点环清晰，触控目标至少 44px。
- 图表提供文本摘要或数据表。
- 支持浏览器 200% 缩放而不遮挡主要操作。

## 测试要求

- 为金额格式、状态映射、权限指令和校验摘要编写单元测试。
- 为合同创建确认、收款核销、无权限、AI 来源查看编写组件测试。
- 使用 Playwright 覆盖登录、建档、签约、确认、登记收款、核销、AI 合同录入和报表下钻。
- 覆盖加载、空数据、筛选无结果、无权限、字段校验、局部失败、数据过期和依赖故障状态。

## 交付要求

1. 先检查现有代码、路由和设计令牌，不重复建立冲突的组件体系。
2. 提交页面信息架构和组件拆分，再开始编码。
3. 使用模拟 API 时明确集中管理，不把演示数据散落在组件中。
4. 完成后运行类型检查、测试和构建。
5. 启动本地预览，逐页验证桌面与关键断点。
6. 输出已完成页面、复用组件、测试结果、剩余接口依赖和已知限制。

## 禁止事项

- 不把按钮隐藏当作权限控制。
- 不在前端推导正式金额、逾期或资源冲突结论。
- 不让 AI 建议看起来像已经执行的业务结果。
- 不用乐观更新处理合同确认、核销、退款、审批或配置变更。
- 不虚构生产客户、生产金额、用户评价或外部品牌 Logo。
