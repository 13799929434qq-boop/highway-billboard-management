| 属性 | 说明 |

## 全流程 7 个阶段

```text
Phase 1 需求对话     从经营痛点和业务语言中收敛产品范围
Phase 2 功能规划     将需求转化为模块 功能 状态和接口规格
Phase 3 Eval 设计    在开发前定义业务正确性 AI 边界和验收基线
Phase 4 前端设计     生成企业经营后台的页面结构 视觉系统和交互状态
Phase 5 后端开发     建立领域模型 API 权限 事务 审计和 AI 服务
Phase 6 系统集成     对接前后端 文件存储 检索 模型网关和异步任务
Phase 7 产品落地     完成测试 部署 数据迁移 监控和持续迭代
```

## 本案例要解决的问题

- 广告牌点位和广告面缺少统一资源台账，空置、预占、出租、维修等状态难以核对。
- 合同、收费计划、应收账单和收款流水分散管理，经营口径与现金口径容易混淆。
- 收款核销、客户挂账和待认领收款缺少清晰闭环，余额与用途难以追溯。
- 临期合同、逾期应收、证件过期和巡检缺陷缺少统一待办和风险视图。
- AI 可以提高合同录入和经营分析效率，但必须受到业务规则、权限和人工确认约束。

## Vibe Coding 的核心原则

1. 先统一业务语言，再生成页面和代码。
2. 先确定不可破坏的业务规则，再设计接口和数据表。
3. 先写 Eval 和验收标准，再进入编码阶段。
4. 正式业务事实由确定性规则计算，AI 只做提取、检索、解释和建议。
5. 前端按钮权限不是安全边界，所有权限和数据范围都要在服务端重新校验。
6. 合同、财务和审批记录保留历史，不通过覆盖或删除修正正式事实。
7. AI、缓存或向量检索故障时，核心合同与财务流程仍然可用。

## 建议的实操方式

按文件顺序执行，每个阶段都把产物提交到版本库。进入下一阶段前，先用本阶段的检查清单复核。若需求、规则或范围发生变化，应同步更新功能规格、Eval 和提示词，避免文档与实现分叉。
