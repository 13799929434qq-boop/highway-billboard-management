# Phase 6 系统集成

> 对接前端、后端、文件、AI、检索和云资源，并验证完整业务闭环

## 集成目标

集成阶段的重点不是让接口“能通”，而是确保同一业务对象在页面、API、数据库、文件、审计和 AI 来源之间保持一致。优先验证合同确认、应收生成、收款核销、权限隔离和 AI 待确认草稿五条关键链路。

## 一 联调准备

### 环境变量

```text

```

使用 `.env.example` 描述变量，不提交真实密钥。测试和预览环境只使用虚构或脱敏数据。

### 契约同步

1. 后端生成 OpenAPI 文档。
2. 前端从 OpenAPI 生成或校验 TypeScript 类型。
3. 双方统一日期、金额、枚举、分页、错误码和追踪编号格式。
4. 对仍在开发的接口使用集中式 Mock，不在组件中散落演示数据。

## 二 核心链路联调

### 链路 A 合同创建与确认

```text
前端填写合同
  → 保存草稿
  → 后端校验客户 资源 租期 金额 附件 权限
  → 前端展示规则结果与影响摘要
  → 不同用户执行确认
  → 后端事务内写入确认 租期占用 应收 审计
  → 前端刷新合同详情和应收列表
```

验证点：重复点击不重复生成应收；并发竞争同一租期只能一个成功；失败时不留下部分占用。

### 链路 B 收款与核销

```text
登记收款流水
  → 识别客户或进入待认领
  → 查询可核销应收
  → 前端提交分配明细与幂等键
  → 后端锁定相关余额并校验
  → 写入核销分配 更新派生状态 写审计
  → 返回最新收款余额和应收余额
```

验证点：金额使用字符串或定点小数传输；禁止超额；并发请求不造成负余额。

### 链路 C AI 合同录入

```text
前端申请上传
  → 后端校验并生成私有上传凭证
  → 文件进入 OSS
  → 创建 AI 任务
  → OCR或文本抽取
  → 模型提取结构化字段
  → 规则服务校验
  → 前端轮询或订阅任务状态
  → 展示字段 来源和待确认标识
  → 用户确认后创建普通合同草稿
```

验证点：模型失败不产生正式合同；来源可打开；无权用户不能读取任务和附件。

### 链路 D AI 经营问答

```text
用户提问
  → 服务端确认身份与数据范围
  → 分类为结构化查询或文档检索
  → 调用受控工具或 Milvus
  → 再次校验来源权限
  → 模型生成回答
  → SSE 返回事实 建议 来源和元数据
```

验证点：事实与建议分开；无依据时拒答；提示注入不能扩大权限。

## 三 文件与向量检索集成

### 文件处理

- OSS Bucket 使用私有权限。
- 数据库只保存对象键、哈希、类型、大小、业务关联和上传者。
- 下载通过短期签名地址或受控接口完成。
- 对文件类型、大小、病毒扫描结果和哈希去重进行校验。
- 删除业务附件采用逻辑解绑和保留策略，不破坏审计链。

### 文档入库

```text
文件解析 → 清洗 → 按标题或语义分块 → 生成 Embedding
→ 写入 Milvus → 保存索引版本和来源定位 → 标记任务完成
```

向量元数据至少包含组织、业务对象、文档 ID、页码或段落、权限标签、索引版本。重新索引使用新版本，完成后再切换，不让查询命中半成品索引。

## 四 错误处理和降级

| 故障 | 用户反馈 | 系统行为 |
|---|---|---|
| FastAPI 校验失败 | 显示字段级错误和修正方法 | 不提交正式写入 |
| MySQL 事务冲突 | 提示数据已变化，请刷新重试 | 回滚全部写入 |
| Redis 不可用 | 提示部分加速或任务能力异常 | 安全读请求回源，依赖锁的写操作拒绝 |
| OSS 不可用 | 文件上传或预览失败，可重试 | 不创建缺少附件的正式记录 |
| Milvus 不可用 | 文档问答暂不可用 | 核心业务正常运行 |
| 模型超时 | AI 任务失败或可重试 | 规则事实和普通页面正常运行 |
| SSE 中断 | 保留已生成内容并提供重试 | 记录任务状态，不重复执行业务写入 |
| 部分图表失败 | 显示局部错误和更新时间 | 其他模块继续显示 |

## 五 联调顺序

1. 身份、会话、角色与数据范围。
2. 点位、广告面、客户基础数据。
3. 合同草稿、校验、确认和应收生成。
4. 收款、认领、挂账和核销。
5. 工作台指标、风险和下钻。
6. 文件上传、附件权限和下载。
7. AI 合同提取、来源和人工确认。
8. RAG 问答、结构化工具和流式输出。
9. 巡检维修、导出和系统配置。

## 六 集成测试清单

- 登录后刷新页面，会话和最近筛选条件正确恢复。
- 直接访问无权 URL 时，页面和接口均拒绝。
- 合同确认成功后，租期、应收、工作台和审计同步更新。
- 合同确认失败后，所有相关表保持原状态。
- 收款核销后，收款余额、应收余额、客户视图和报表口径一致。
- AI 字段来源能定位到原文件，修改字段后保留人工变更痕迹。
- AI 回答中的每个来源都在当前用户授权范围内。
- AI、Redis 或 Milvus 停止时，合同和财务主流程仍可完成。
- 所有错误响应含追踪编号，前后端日志可关联。

## 七 联调完成标准

- P0 业务链路在固定数据集上连续执行通过。
- OpenAPI 与前端类型无未处理差异。
- 无跨权限数据泄露、重复写入、负余额或孤立正式记录。
- 关键操作均有审计记录和可理解错误信息。
- AI 输出带来源、权限范围和待确认状态，且降级路径可验证。
