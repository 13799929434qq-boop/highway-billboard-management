# 前后端开发提示词（参考）

状态：**参考模板**。使用时必须填入具体 TAPD ID 和验收标准，不能把模板本身当作开发需求。

## 前端任务模板

```text
请实现高速公路广告牌管理系统的前端需求：<TAPD ID 和需求名称>。

开始前：
1. 读取需求基线中该 TAPD ID 的用户故事和验收标准。
2. 读取领域上下文、现行技术架构和相关产品设计文档。
3. 检查 frontend/package.json、现有路由、组件、样式和测试；以仓库实际安装依赖为准，不擅自引入新框架。

实施要求：
- 只实现本需求范围，不根据参考材料扩展页面或业务状态。
- 所有正式金额、权限、冲突和状态结论由后端返回，前端负责展示和交互反馈。
- 覆盖加载、空数据、无权限、校验失败、网络失败和重复提交状态。
- 复用现有组件和设计规范，保证键盘操作、清晰焦点和必要的文本状态说明。
- 为关键交互补充测试，完成后运行类型检查、测试和构建。

交付时说明：修改文件、完成的验收项、测试结果、接口依赖和已知限制。
```

## 后端任务模板

```text
请实现高速公路广告牌管理系统的后端需求：<TAPD ID 和需求名称>。

开始前：
1. 读取需求基线中该 TAPD ID 的用户故事和验收标准。
2. 读取领域上下文、架构决策和现行技术架构。
3. 检查 backend/requirements.txt、现有模块、数据库模型、迁移和测试；以仓库实际依赖和既有结构为准。

实施要求：
- 只实现本需求范围，不根据参考材料新增 AI、缓存、向量检索或云服务。
- 权限和数据范围必须在服务端执行，不能信任前端隐藏按钮或客户端传入的组织范围。
- 涉及合同、应收、收款、核销、退款和状态变化时，明确事务、幂等、并发和审计要求。
- 正式记录不得通过物理删除或直接覆盖来修正历史。
- 先编写失败测试，再完成最小实现；补充正常、边界、无权限和失败回滚测试。
- 完成后运行相关测试，并检查迁移、接口错误码和日志是否泄漏敏感信息。

交付时说明：修改文件、数据库变化、完成的验收项、测试结果、部署影响和已知限制。
```

## 禁止事项

- 不在提示词里写死尚未批准或尚未安装的库。
- 不使用自定义 F1～F8、P0/P1 等编号替代 TAPD 基线编号。
- 不把广告面改成合同租赁和租期占用单位；现行基线使用广告牌。
- 不让 AI 建议看起来像已经执行的正式业务结果。
- 不使用虚构的生产客户、金额、评价或品牌资料。
