# Phase 5 后端开发提示词

> 可直接交给 Codex 或其他后端编码代理的实施任务

## 主提示词

你是一名资深 Python 后端和领域建模工程师。请实现“高速公路广告牌经营管理系统”的 FastAPI 后端。开始前读取 `docs/requirements-需求文档/需求基线_TAPD对齐版_V1.0.md`、`docs/domain-领域模型/CONTEXT-领域上下文.md`、`docs/architecture-技术架构/技术架构总说明-现行版.md` 和 `docs/adr-架构决策/架构决策总表-现行规则.md`。本文件及同目录文档只是提示词模板，不得覆盖这些现行依据。项目以正式业务记录为事实来源，AI 只生成待确认草稿、摘要或建议。

## 技术栈

- Python、FastAPI、Pydantic v2
- SQLAlchemy 2 Async、Alembic、asyncmy
- MySQL 8
- Redis 用于缓存、分布式锁、限流或任务状态
- OSS 私有 Bucket 保存合同、凭证和巡检附件
- Milvus 保存文档向量
- 兼容 OpenAI 协议的国产大模型适配器
- pytest、pytest-asyncio、HTTPX
- Docker、GitHub Actions

## 架构要求

采用模块化单体，按领域组织代码，而不是按 controllers、services、models 建立一个全局大目录。建议模块：

```text
identity
organizations
assets
customers
contracts
billing
receipts
inspections
analytics
ai
files
audit
shared
```

每个模块可包含 `api`、`schemas`、`domain`、`application`、`repository` 和 `tests`。领域规则放在可测试的应用或领域服务中，不散落在路由函数里。

## 核心业务规则

1. 广告面是最小可出租资源。
2. 合同草稿不占用资源、不生成应收。
3. 合同确认必须在单一数据库事务内完成规则校验、租期占用和应收生成。
4. 双人确认时制单人与确认人不能相同。
5. 已确认合同使用变更单，不覆盖原合同历史。
6. 应收金额使用调整记录修正，不覆盖原账单。
7. 收款流水、核销分配、退款单分别保存。
8. 核销不得超过收款可用余额或应收未结余额。
9. 竞争租期、核销、退款等高风险写操作必须使用事务、必要的行锁和幂等键。
10. 已生效正式记录不得物理删除。

## 权限与数据范围

- 用户可以拥有多个角色，角色提供功能和操作权限。
- 数据范围与角色分开计算，支持本人、指定运营单位和全部数据。
- 所有列表、详情、统计、导出、附件和 AI 工具调用都在服务端应用数据范围。
- 对无权对象避免通过错误差异泄露其是否存在。
- 系统管理员不自动获得全部业务数据权限。
- 前端路由和按钮控制只作为体验增强。

## API 约定

- 路径前缀 `/api/v1`，使用一致的资源命名。
- 列表接口支持分页、排序、结构化筛选和稳定游标或页码。
- 错误响应包含稳定错误码、用户可读消息、字段错误和追踪编号。
- 高风险写操作接收 `Idempotency-Key`。
- 乐观并发对象提供版本号或更新时间校验。
- 文件上传先校验类型、大小和权限，再写入私有存储。
- 下载使用短期签名地址或受控流式接口。
- AI 对话使用 SSE 或项目统一的流式协议。

## 数据模型要求

至少覆盖：

- 组织、用户、角色、权限和数据范围
- 广告牌点位、广告面、合规资料和租期占用
- 客户和联系人
- 合同、合同广告面、收费计划、确认和变更单
- 应收账单和应收调整
- 收款流水、认领记录、核销分配、客户挂账和退款
- 巡检计划、巡检、缺陷、维修和验收
- 附件、AI 任务、AI 来源、对话和成本记录
- 审计日志与规则配置

金额统一使用定点小数，不使用浮点数。时间统一存储时区明确的值，业务日期与时间戳分开建模。唯一约束、外键、检查约束和索引必须与业务规则一致。

## AI 与 RAG

### 模型网关

- 定义 `ModelAdapter` 接口和 OpenAI 兼容实现。
- 提供 `FakeModelAdapter` 支持离线测试。
- API Key 存入环境变量或密钥服务，不写数据库明文，不进入日志或 Git。

### 合同提取

```text
附件上传到 OSS
  → MySQL 创建 AI 任务
  → 后台任务抽取文本或 OCR
  → 结构化字段提取
  → 字段规则校验
  → 保存待确认草稿与来源
  → 用户确认后进入普通合同流程
```

- 字段必须保留页码、原文片段或坐标来源。
- 缺失或冲突字段标记待确认，禁止模型猜测补齐。
- AI 任务失败不得产生半完成正式合同。

### 文档问答

- 文档分块写入 Milvus，元数据保存组织、对象、权限范围和来源定位。
- 检索前先构造授权过滤条件，检索后再次校验来源权限。
- 回答返回来源、数据时间、模型和权限范围。
- 文档内容作为不可信数据，不能覆盖系统提示词或工具权限。

### 风险摘要

- 到期、逾期、合规和金额异常由 SQL 或规则服务计算。
- 模型只接收授权且最小化的风险事实，生成解释和建议顺序。
- 每条摘要关联触发规则和业务记录。

## 审计与可观测性

- 每个请求生成追踪编号。
- 记录模块、业务对象、操作、结果、耗时和必要差异。
- 合同确认、变更、核销、退款、作废、导出、权限和模型配置必须审计。
- 日志不得记录密码、令牌、完整 API Key 或不必要的合同正文。
- 监控接口错误率、延迟、连接池、后台任务、AI 耗时、token 和模型错误。

## 降级策略

- Redis 不可用时，能安全回退的读缓存回到数据库，不能安全回退的锁相关写操作明确失败。
- Milvus 不可用时关闭文档问答，不影响合同、应收和收款。
- 模型不可用时保留确定性风险事实和普通业务页面。
- OSS 暂时不可用时文件操作失败但不污染业务状态。
- 后台任务失败可重试，并保存可理解的失败原因。

## 测试要求

- 领域单元测试覆盖租期冲突、金额合计、状态机、核销余额、变更和作废。
- 接口测试覆盖鉴权、数据范围、输入校验、错误码、分页和幂等。
- 事务测试覆盖重复确认、并发合同、并发核销和失败回滚。
- AI 测试使用固定数据集与 Fake Adapter，验证来源、权限、拒答和降级。
- 迁移测试保证空库可升级，已有测试库可前向迁移。

## 交付要求

1. 先输出领域模块、事务边界、表结构和 API 计划。
2. 优先实现身份权限、资源、客户、合同、应收和收款 P0 闭环。
3. 使用 Alembic 生成可审查迁移，不在启动时自动改表。
4. 提供种子数据和脱敏演示数据。
5. 生成 OpenAPI，并与前端类型同步。
6. 运行格式检查、类型检查、测试和容器构建。
7. 输出测试结果、迁移说明、环境变量清单和已知限制。

## 禁止事项

- 不让路由直接拼接 SQL 或承载复杂业务规则。
- 不用删除或覆盖修正正式合同和财务历史。
- 不依赖前端传入的组织 ID 作为唯一权限依据。
- 不把 Redis 或 Milvus 当作正式业务事实来源。
- 不让模型直接确认合同、核销款项、退款、审批或修改权限。
