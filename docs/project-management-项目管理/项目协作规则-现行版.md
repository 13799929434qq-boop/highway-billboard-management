# 项目协作规则（现行版）

本文件集中说明项目的任务跟踪、优先级、任务状态和领域文档使用规则。根目录 [`AGENTS.md`](../../AGENTS.md) 是供 Codex 等开发代理自动发现的控制文件，必须保留在项目根目录；本文件是便于人员阅读的详细说明。

## TAPD 任务跟踪

- 工作区：魔幻陀螺组。
- 工作区 ID：`64099159`。
- 正式范围：[`需求基线_TAPD对齐版_V1.0.md`](../requirements-需求文档/需求基线_TAPD对齐版_V1.0.md)。
- 引用任务时使用需求基线中的 TAPD ID，不从旧需求清单、临时快照或 GitHub Issues 推导范围。
- 范围、优先级或任务状态变化时，应同步维护 TAPD 和需求基线。
- Pull Request 用于代码评审，不作为需求受理或任务分流队列。

## 优先级与开发顺序

- 只使用 TAPD 基线中的 `High`、`Middle`、`Low` 优先级。
- 页面编号 P0～P8 表示页面分组，不是 P0/P1 式优先级。
- 同一页面内的 `01`、`02` 等编号表示开发顺序。

## 任务状态标签

| 标签 | 中文含义 | 使用条件 |
|---|---|---|
| `needs-triage` | 待分流 | 尚未判断范围、负责人或处理方式 |
| `needs-info` | 待补充信息 | 缺少继续处理所必需的信息 |
| `ready-for-agent` | 可由代理执行 | 范围、验收标准和依赖已经明确 |
| `ready-for-human` | 需要人工处理 | 需要负责人判断、外部协调或人工操作 |
| `wontfix` | 不处理 | 已明确决定不进入实施 |

如果 TAPD 中实际使用的标签发生变化，应同步更新本表和根目录 `AGENTS.md`。

## 领域文档使用规则

- 修改领域行为前，读取 [`CONTEXT-领域上下文.md`](../domain-领域模型/CONTEXT-领域上下文.md)。
- 修改相关架构或关键业务行为前，读取 [`架构决策总表-现行规则.md`](../adr-架构决策/架构决策总表-现行规则.md)。
- 需求基线和已确认的甲方记录高于术语说明；出现冲突时不得静默覆盖，应指出冲突并等待裁决。
- 在需求、代码、测试和说明中使用领域上下文定义的统一词语，避免使用其中明确排除的同义词。
- 缺少某个术语时，先确认它是否真的属于项目范围；只有业务概念得到确认后才补充领域文档。
- 项目采用单一领域上下文，不为前端、后端或单个页面建立相互冲突的业务词典。

## 代理协作规则

- TAPD 需求和需求基线决定做什么，领域上下文解释业务词语，架构文档决定技术边界。
- 清晰、可执行的需求采用测试驱动开发并进行代码评审。
- 需求不清楚时先澄清，不根据参考文档自行扩展范围。
- OpenSpec 仅在用户明确要求使用时启用，不因关键词自动触发。
- 文档、代码和 TAPD 状态发生实质变化时，应在同一任务中修正相关引用。
