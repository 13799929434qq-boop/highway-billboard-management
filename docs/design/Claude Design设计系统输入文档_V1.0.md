# Claude Design 设计系统输入文档

> 本文件是提供给 Claude Design、Claude Code 或其他设计生成工具的设计源文件。生成界面时必须先读取本文件，再读取对应页面的需求基线。需求基线决定功能，本文件决定信息组织与视觉表达。本文件不得被用于推导新的业务功能。

## 1. 产品与使用场景

产品名称：高速公路广告牌经营管理系统。

产品性质：桌面端企业业务管理系统，用于维护广告牌资产、客户、合同、财务、报表、消息、售后维护和账号权限。

主要用户：运营档案员、合同管理员、财务管理员、售后维护人员、部门领导、系统管理员。

使用环境：办公室桌面电脑，用户会长时间查询台账、核对资料和录入表单。设计应优先保证信息准确、查询效率、状态可理解和错误可恢复。

业务识别要素：路段、地区、运营单位、广告牌编号、三个桩号、经营状态、手续有效期、合同履约和业务留痕。

## 2. 设计目标

界面应呈现“高速公路运营台账”的专业感，而不是通用 SaaS 模板。

1. 列表是业务人员的主要工作区，信息密度适中，允许快速横向比较。
2. 页面结构稳定。相同位置始终承担相同职责，减少用户重新学习。
3. 状态必须同时使用文字，不允许只依赖颜色。
4. 重要风险靠位置、文字和边框共同表达，不使用夸张装饰。
5. 业务事实、AI 建议和系统反馈必须在视觉上明确区分。
6. 不使用没有业务意义的数据卡片、图标或图表填充空白。

## 3. 视觉命题

视觉主题：**公路运营台账**。

道路深灰表现稳定的系统骨架；路牌蓝承担导航、主操作和当前选择；风险橙只用于业务提醒和关键视觉锚点；纸面白与冷灰承载密集数据。

唯一重点表达：页面的业务工作区。其他元素保持克制，不与表格、表单和档案信息争夺注意力。

禁止将“高速公路”理解为装饰性公路插画、地图背景、车辆图片或大量交通图标。

## 4. 设计令牌

### 4.1 色彩

| 名称 | 值 | 用途 |
|---|---|---|
| 文字主色 | `#17212B` | 标题、正文、主要数据 |
| 道路深灰 | `#202B35` | 主侧边栏、稳定结构 |
| 路牌蓝 | `#245A7A` | 主按钮、选中项、链接、焦点 |
| 风险橙 | `#C45D20` | 风险提醒、关键视觉锚点 |
| 页面底色 | `#F4F6F7` | 页面工作区背景 |
| 容器白 | `#FFFFFF` | 表格、表单、详情内容 |
| 默认边框 | `#CFD7DC` | 容器和数据分隔 |
| 次要文字 | `#65717C` | 描述、帮助信息 |
| 成功 | `#24704C` | 有效、完成 |
| 失败 | `#A73C32` | 过期、失败、字段错误 |

约束：

- 路牌蓝是唯一常规主色。
- 风险橙不得用于普通按钮或大面积背景。
- 禁止渐变、霓虹发光和纯装饰性色块。
- 页面中性色面积应大于彩色面积。

### 4.2 字体

字体栈：`Noto Sans SC`, `Source Han Sans SC`, `Microsoft YaHei`, sans-serif。

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 22/30 | 700 | 页面唯一主标题 |
| 区域标题 | 16/24 | 700 | 内容分区 |
| 组件标题 | 14/22 | 700 | 表单组、面板标题 |
| 正文 | 14/22 | 400 | 主要说明和表单内容 |
| 表格正文 | 13/20 | 400 | 台账数据 |
| 辅助文字 | 12/20 | 400 | 提示、范围、元信息 |

标题使用中文句式，不使用英文全大写、超宽字距或装饰性斜体。

### 4.3 间距与尺寸

基础网格：4px。

允许的主要间距：4、8、12、16、24、32px。

| 对象 | 尺寸 |
|---|---|
| 顶部栏高度 | 56px |
| 左侧导航宽度 | 208px |
| 页面内容边距 | 24px |
| 默认控件高度 | 32px |
| 大型控件高度 | 40px |
| 表头高度 | 40px |
| 默认表格行高 | 48–52px |
| 快速详情抽屉 | 420–440px |

### 4.4 圆角与阴影

| 名称 | 值 | 用途 |
|---|---|---|
| 微小圆角 | 2px | 表格外框、结构容器 |
| 控件圆角 | 4px | 输入框、按钮、导航项 |
| 外壳圆角 | 6px | 原型浏览器外壳 |
| 全圆角 | 999px | 状态标签、头像，除此之外禁用 |

业务页面默认不使用卡片阴影。仅原型外壳、抽屉或明确浮于页面之上的层级可以使用轻阴影。

## 5. 页面骨架

```text
┌────────────────────────────────────────────────────────────┐
│ 产品名称 / 面包屑                         用户与身份范围 │ 56
├──────────────┬─────────────────────────────────────────────┤
│              │ 页面标题                      页面级操作 │
│ 业务导航 208 │ 页面说明                                   │
│              ├─────────────────────────────────────────────┤
│ 当前项       │ 筛选 / 标签页 / 步骤等上下文控制           │
│              ├─────────────────────────────────────────────┤
│ 数据范围     │ 主业务内容：台账、档案或表单               │
└──────────────┴─────────────────────────────────────────────┘
```

对齐规则：页面标题、筛选区、表格和分页左边界一致。页面级主要操作放在标题区右侧。主按钮每个区域最多一个。

## 6. 核心组件规则

### 6.1 左侧导航

- 深灰底色，当前项使用白色块和左侧 4px 风险橙定位线。
- 菜单只显示当前用户有权限访问的模块。
- 底部明确显示当前数据范围，不把数据范围混入角色名称。

### 6.2 筛选区

- 使用白底、细边框和左侧 4px 路牌蓝定位线。
- 第一行放筛选字段与“查询”“重置”。
- 第二行显示已经生效的条件，说明列表与导出使用同一条件。
- 没有查询条件时不显示空标签。

### 6.3 数据表格

- 表头使用冷灰底色，列名左对齐。
- 标识信息在左侧，状态与操作靠右。
- 整行可进入详情时仍保留明确的文字操作，避免用户猜测。
- 状态使用短文字标签；临期和过期必须显示具体文字。
- 没有权限的数据不进入列表，不使用遮罩展示。

### 6.4 按钮

- 主按钮：路牌蓝底、白字，用于当前区域最重要的提交或进入动作。
- 次按钮：白底、灰色边框。
- 文字操作：路牌蓝文字，用于表格行操作。
- 危险操作：只有真正不可逆或产生重大状态变化时使用失败色。
- 文案使用明确动作，例如“新建广告牌”“保存档案”“重新保存”。

### 6.5 表单

- 按业务认知分组，不按数据库字段分组。
- 标签位于输入框上方；必填项显示 `*`。
- 错误紧邻字段，并说明如何修复。
- 保存失败必须保留已填写内容。
- 三个桩号是三个独立字段，不得合并或自动覆盖。

### 6.6 快速详情与完整档案

- 快速详情用于核对少量高频信息，不承载完整编辑。
- 完整档案用于查看全部字段、手续、照片、变动历史和操作记录。
- 关闭快速详情后保留原筛选、页码和滚动位置。

### 6.7 状态页

每个状态必须回答三个问题：发生了什么、当前内容是否保留、用户下一步做什么。

必须覆盖：加载中、筛选无结果、尚无数据、保存失败、无权限、保存成功。

## 7. 业务文案约束

必须使用项目统一术语：

- “广告牌”表示整块经营设施。
- “广告面”只表示广告牌的物理展示面。
- 使用“经营状态”，不用“使用状态”。
- 使用“合同确认”，不用“审批”。
- 使用“作废”，不用“删除历史记录”。
- “角色”和“数据范围”分别表达，不得混为一个字段。

界面文字使用主动、直接的中文，不写营销口号，不使用“提交”代替具体动作。

## 8. 权限表达

- 无功能权限：入口不显示。
- 有功能权限但无数据权限：数据不出现在列表；直接访问时显示“无权访问该档案”。
- 无导出权限：不显示导出按钮。
- 页面应显示当前身份与当前数据范围，帮助用户理解结果范围。

## 9. 禁止项

1. 不得增加需求基线未定义的地图、批量编辑、自定义首页、审批中心或数据大屏。
2. 不得使用一排同形 KPI 卡片充当首页或页面头部。
3. 不得给每个标题配置装饰性图标。
4. 不得在所有容器上使用相同的大圆角和阴影。
5. 不得用颜色作为状态的唯一信息来源。
6. 不得为了填满页面编造统计数据、合同数据或风险结论。
7. 不得把 AI 结果直接写入正式业务记录；AI 建议必须等待用户确认。

## 10. P2 广告牌资产管理页面约束

需求范围只来自需求基线 P2 的七项：路段/地区/运营单位维护、广告牌基本信息、三个桩号、证件有效期、现场照片、列表查询、新增/拆除/移位。

### 台账列表

首屏结构顺序：页面标题与操作 → 查询条件 → 生效条件 → 结果数量 → 数据表格 → 分页。

建议列：广告牌编号、名称、所属路段、现场桩号、经营状态、手续状态、操作。列数超过可用宽度时允许横向滚动，不压缩到无法阅读。

### 快速详情

显示：名称、编号、经营状态、现场照片缩略图、路段、运营单位、三个桩号、规格和手续摘要。提供“打开完整档案”和“编辑”。

### 完整档案

按基本信息、三类手续、现场照片、资产变动、操作记录组织。基本信息区域必须同时展示三个桩号。

### 新建与编辑

分为基本与归属、位置与规格、手续与照片、检查保存四个认知步骤。具体字段及校验以需求基线为准，文档未规定的字段标记“待确认”。

## 11. 生成指令

使用本文件生成界面时：

1. 先读取需求基线中的目标页面功能与验收标准。
2. 只生成目标页面需要的功能，不补全未定义业务。
3. 先套用本文件的令牌、页面骨架和组件规则。
4. 使用真实业务术语；示例数据必须明确属于演示数据。
5. 生成后逐项检查第 12 节，不符合时先修正再展示。

## 12. 验收清单

- [ ] 页面功能全部能在需求基线中找到来源。
- [ ] 主导航、身份和数据范围清楚。
- [ ] 页面标题、筛选区、表格左边界一致。
- [ ] 主操作每个区域不超过一个。
- [ ] 圆角只使用 2、4、6 和全圆角四档。
- [ ] 状态有文字，不依赖颜色区分。
- [ ] 错误说明恢复方式，保存失败保留内容。
- [ ] 没有通用 KPI 卡片、渐变、霓虹或装饰图标。
- [ ] 没有新增地图、批量编辑、自定义首页或审批中心。
- [ ] 页面在 1440×900 下完整可用，在 1024px 宽度下不遮挡主要操作。

## 13. 待确认

- 正式品牌 Logo、品牌字体与对外品牌色尚未提供。目前使用文字标识和本文件定义的产品界面色。
- 上传文件允许的格式、单文件大小和数量上限需要业务确认。
- 证件“临近到期”的具体天数阈值需要业务确认。
- 新建/拆除/移位的确认角色和驳回流程细节需要业务确认。
