# 架构决策总表（现行规则）

本文件汇总高速公路广告牌经营管理系统当前有效的架构决策。修改部署方式、AI 能力、合同与资金记录或数据权限前，应同时阅读本文件和 `../domain-领域模型/CONTEXT-领域上下文.md`。

## 一、部署方案

### 分阶段采用 Vercel 和阿里云部署

项目个人开发和试用阶段将 Vue Vite 前端与 FastAPI 后端部署在 Vercel，并连接测试用途的企业级外部设施，以获得低运维成本、预览部署和快速迭代能力。

客户正式使用或存储真实合同及财务数据之前，前端迁移至阿里云 OSS 与 CDN，FastAPI 以 Docker 部署至阿里云 ECS，并通过内网连接 RDS MySQL、Redis、OSS 和 Milvus。该方案用于平衡早期开发效率、Vercel Python Runtime 的 Beta 风险、国内网络质量和数据安全要求。

## 二、AI 使用与安全边界

### AI 只提供建议，不直接变更正式业务数据

AI 可以提取合同字段、生成待确认草稿、检索文档并形成经营风险摘要，但不得直接签订合同、核销款项、审批业务或修改正式记录。合同、金额、状态和权限相关变更必须由确定性业务规则校验，并由具备权限的用户确认。

### AI 解释风险，不判定业务事实

合同到期、应收逾期、证件过期和金额异常等事实由可测试的确定性规则计算。AI 只负责汇总、解释和提出处理建议。每条 AI 风险摘要必须关联触发规则和来源业务记录，确保结论可以复核。

### AI 继承当前用户的数据权限

AI 检索、模型工具调用和摘要生成必须在服务端重新执行当前用户的功能权限与运营单位数据范围校验，AI 不拥有独立的超级权限。该规则适用于结构化查询、合同文档检索和风险摘要，防止通过对象名称、统计数字或文档片段泄露无权访问的信息。

## 三、合同与资金记录规则

### 生效后的合同和资金记录不得覆盖历史

合同确认后，通过变更单记录租期、资源或价格调整；应收金额通过调整记录修正；收款和退款分别保留独立记录；已经核销的数据不得删除。

该规则虽然会增加数据结构和操作流程，但能够保证合同履约、资金余额和经营报表可以复核，并满足责任追溯要求。

## 四、权限与数据访问规则

### 系统管理权限与业务数据权限分离

系统管理员负责账号、角色、配置和运行管理，但不因管理员身份自动获得合同、财务和敏感附件的全部查看权限。业务数据访问仍需单独授予角色和数据范围，以降低技术管理账号滥用或泄露业务信息的风险，并使权限审计更加清晰。

- 规则发生变化时，应在 Git 提交记录中说明原因；历史版本通过 Git 查询，不在当前目录保留重复副本。
