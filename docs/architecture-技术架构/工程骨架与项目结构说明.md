## 二、仓库组织：企业级 monorepo

```
公路广告牌项目/
├─ frontend/            # 前端工程（独立构建/测试/部署）
├─ backend/             # 后端工程（独立构建/测试/部署）
├─ docs/                # 项目说明、领域、需求、架构、设计、开发与归档文档
├─ openspec/            # 规格与变更
├─ README.md            # docs 文档入口指引
├─ AGENTS.md            # AI 代理协作约定
└─ .gitignore
```

- 前后端同在一个版本库，但**构建、测试、依赖、部署相互独立**；
- 选 monorepo 理由：4 人全栈团队，避免跨仓版本对齐与 CI/CD 重复；
- **拆仓触发条件**：团队规模扩大、前后端需独立权限或独立发布节奏时，再拆为两个仓库。

## 三、后端目标结构与分层

```
backend/
├─ app/
│  ├─ main.py              # 应用入口、中间件、路由挂载
│  ├─ core/
│  │  ├─ config.py         # 配置（pydantic-settings，读 .env）
│  │  ├─ security.py       # 密码哈希、会话生成
│  │  └─ exceptions.py     # 统一异常与处理器
│  ├─ db/
│  │  ├─ session.py        # 引擎、会话工厂、依赖注入
│  │  └─ base.py           # Declarative Base
│  ├─ models/              # SQLAlchemy 模型（按模块：user/board/customer/contract/finance…）
│  ├─ schemas/             # Pydantic 请求/响应模型
│  ├─ api/
│  │  └─ v1/               # 路由（按模块拆分）
│  ├─ services/            # 业务逻辑（合同计价、核销、报表口径…）
│  └─ dependencies/        # 公共依赖（鉴权、权限、分页）
├─ alembic/                # 迁移脚本（versions/）
├─ tests/                  # 测试（按 api/services 分层）
├─ requirements.txt
├─ pytest.ini
└─ .env（不入库）
```

分层职责：`api` 只做参数与响应；`services` 承载业务规则；`models` 定义数据；`schemas` 定义出入参；`core/db` 为基础设施。依赖方向单向：api → services → models。

## 四、前端目标结构与分层

```
frontend/
├─ src/
│  ├─ main.ts
│  ├─ App.vue
│  ├─ router/              # 路由表 + 登录/权限守卫
│  ├─ stores/              # Pinia（用户/会话、权限）
│  ├─ api/                 # 接口封装（axios 实例 + 各模块 api）
│  ├─ views/               # 页面（按 P1~P8 模块组织）
│  ├─ components/          # 可复用组件（通用 + 业务）
│  ├─ composables/         # 组合式逻辑
│  ├─ utils/               # 工具函数
│  ├─ assets/              # 静态资源
│  └─ styles/              # 全局样式
├─ index.html
├─ vite.config.ts
├─ tsconfig*.json
└─ package.json
```

- 页面按 TAPD 模块 P1~P8 建子目录，与需求编号对应；
- 中后台组件库建议引入 **Element Plus**（或由 UI 决定），统一表格/表单/弹窗；
- 路由按角色动态生成，按钮级权限用指令/封装控制。

## 五、前后端通信规范

- 风格：RESTful，统一前缀 `/api/v1`；JSON 交互。
- **统一响应体：**

```json
{ "code": 0, "message": "success", "data": {} }
```

- 分页响应：`data = { "items": [], "total": 0, "page": 1, "page_size": 20 }`。
- 错误码：`0` 成功；业务错误用非 0 码并随 HTTP 状态返回（如 400 参数、401 未登录、403 无权限、404 不存在、409 冲突、500 服务错误）。
- 前端用 axios 实例统一处理：携带 Cookie、401 跳登录、403 提示、统一错误提示。
- 跨域：后端按环境配置 CORS 白名单，仅允许已知前端域名，允许凭证。

## 六、认证与会话

- 方式：**服务端不透明会话 + HttpOnly + SameSite Cookie**，会话存 Redis；不使用前端可篡改的裸 Token。
- 登录成功创建会话并写 Cookie；退出/超时销毁。
- 密码用 bcrypt/argon2 哈希存储，禁止明文。
- 权限：中间件/依赖校验登录态与角色；菜单、数据、按钮三级权限，越权返回 403。
- 账号状态：正常 / 锁定 / 禁用。

## 七、数据库与迁移

- SQLAlchemy 2.x 定义模型，Alembic 管理表结构变更（升级/回滚可追溯）。
- 命名规范：表名、字段名用蛇形小写（`snake_case`）；表名按模块前缀；主键统一 `id`；时间字段 `created_at/updated_at`。
- 每次涉及表结构变更，生成并提交迁移脚本，禁止手工改库不记录。
- 提供种子数据脚本（字典项、初始管理员）。

## 八、配置与环境

- 用 pydantic-settings 读取 `.env`；区分 dev/prod；密钥、连接串不入库。
- 关键配置项：数据库连接、Redis 连接、会话密钥、CORS 白名单、会话超时、锁定阈值与时长、环境名。
- **业务安全数值（连续错 5 次、锁定 15 分钟、超时 30 分钟）为团队拟定默认值，须可配置并经甲方确认**，不硬编码。

## 九、代码规范

- 前端：ESLint + Prettier；后端：ruff + black；保存自动格式化。
- 命名：前端组件 PascalCase、变量/函数 camelCase；后端蛇形；常量大写。
- 提交信息遵循 Conventional Commits：`feat/fix/docs/refactor/test/chore: 描述`。

## 十、测试

- 后端 pytest（API + services），前端 Vitest（组件/工具）；测试目录与源码对应。
- 金额计算、状态流转、权限、核销等关键规则必须有自动化测试。
- 测试用例与报告见 `09_测试文档/`；结果回填需求追踪矩阵。

## 十一、Git 协作（功能分支）

- `main` 受保护，不直接提交；开发从 main 切功能分支：`feature/p1-01-login`、`fix/...`。
- 完成后自测 + 评审通过，合并回 main；合并要求构建/测试通过。
- `.gitignore` 忽略：node_modules、.venv、dist、.env、缓存、本地 IDE 文件。

## 十二、部署架构（分阶段，ADR-0001）

- 前期：前端 Vercel 托管 + 后端/数据库上云，快速可演示；
- 后期：整体迁移阿里云（建议容器化 Docker），自有域名与环境变量；
- 发布前过构建/测试/迁移；准备回滚方案；上线资源（服务器、域名）由甲方提前准备。

## 十三、本地开发启动

**前置：** Node 22 + pnpm；Python 3.14；本地 MySQL、Redis 运行。

**后端：**
```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# 配置 .env；alembic upgrade head（引入后）
uvicorn app.main:app --reload      # http://127.0.0.1:8000 ，文档 /docs
```

**前端：**
```powershell
cd frontend
pnpm install
pnpm dev                           # http://127.0.0.1:5173
```
