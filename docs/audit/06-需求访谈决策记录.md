## 补充范围原则

原始 PDF §3.7 把合同到期、欠费通知列为可选；§4.4 要求记录合规证件并在临期时提醒。两类提醒按不同优先级处理。原始 PDF 未提出 AI、地图或独立广告面签约，因此不能仅凭 PRD、SRS 或 Backlog 将其认定为甲方首期必需功能。

## 第三轮：调研报告的其余开放事项

依据用户“原始 PDF 有要求按原文，没有规定的按建议”的指示，以下是补充方案。该表仅是本次需求访谈采用的设计方向，不能替代甲方确认。涉及准确天数、金额、文件限制等值，建议值在真实业务样本验证前不得作为已批准验收阈值。

| 调研问题 | 建议方向 | 与原始 PDF 的关系 |
|---|---|---|
| §十二6 合同是否审批 | 合同由制单人提交、另一名有合同确认权限的人员确认后生效；驳回回到草稿并保留意见。 | PDF 只给草稿/生效等状态，未规定确认角色；补足控制点。 |
| §十二7 变更、续签、提前解除 | 均形成独立申请和历史记录，由非制单人确认；涉及收费变化时生成调整记录，不覆盖原应收或收款。 | PDF 要求合同状态及操作追溯，具体变更规则未定。 |
| §十二8 路政费、保险费自动生成应付 | 首期登记和查询应付/付款；自动生成放后续，除非甲方提供稳定、可核验的计费依据。 | PDF 要求支出和资金流水，未要求自动生成。 |
| §十二9 售后维修费自动生成应付 | 维修验收后由财务核对并登记应付，不直接自动入账；自动化后续评估。 | PDF 未要求售后自动应付。 |
| §十二10 提醒提前天数 | 合规证件到期采用 30 天、7 天、到期日三级提示作为待验证默认值；合同到期/欠费提醒保留可配置，通知渠道和阈值另经样本验证。 | PDF §4.4 要求合规临期提醒；§3.7 将合同到期/欠费提醒列可选。 |
| §十二11 滞纳金 | 首期不自动计算；若实际合同约定存在，可先保留人工登记和来源依据，后续再定计算规则。 | PDF 未提出滞纳金。 |
| §十二12 售后优先级 | 售后处理建议列 Should，不挤占原始 PDF 的资源、合同、资金和四张报表主线。 | PDF 未将售后列入必需功能。 |
| §十二13 文件格式与大小 | 建议图片 JPG/PNG 单文件不超过 10 MB，合同/凭证 PDF 单文件不超过 20 MB；保留原文件名、上传人和时间。 | PDF 要求照片和业务附件，但未给格式/大小。数值待真实文件样本验证。 |
| §十二14 历史 Excel 导入 | 首期迁入有效资源、客户、合同、未结应收及可核对的已收/欠款；实际追溯起始年、全量历史流水取决于甲方台账样本与核对要求。 | PDF 要求停止使用 Excel 管业务且与 Excel 对账，不明确迁移年限。 |
| §十二15 批量导入 | 首期为迁移提供受控模板和校验/回滚；上线后的日常批量导入作为后续需求单独确认。 | PDF 未要求日常批量导入；迁移工具服务于上线切换。 |

## 范围与冲突收敛建议

- 四张核心报表及筛选、Excel 导出按原始 PDF §3.5 保持首期必需；Backlog 中将报表列为 Should 的优先级应修订。
- 路政、保险、年审信息和合规临期提醒按原始 PDF §4.4 保持首期必需；合同到期/欠费通知按 §3.7 保持可选。
- 所有收款和付款均保留独立资金流水，账单与收款分开；应付自动生成、AI、地图、独立广告面签约均不得因后续文档出现而升级为原始必需。
- 对已有关联合同、应收或收款的记录，不执行破坏历史的物理删除；提供作废/停用、原因和审计。PDF §五要求“能删”，可通过对用户可见的撤销能力实现，但正式解释仍需客户确认。
