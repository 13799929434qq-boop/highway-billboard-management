## Context

当前仓库处于绿地阶段，尚无前后端工程。目标架构已确定为 Vue 3 + Vite + TypeScript 管理端、FastAPI 模块化单体、MySQL 8.0 正式事实库和 Redis 缓存/限流设施；早期部署到 Vercel，正式使用前迁移到阿里云。认证将成为后续岗位权限、数据范围与操作日志的主体来源，同时必须遵守 ADR-0005：系统管理身份不自动获得业务数据访问权。

## Goals / Non-Goals

**Goals:**

- 建立可供页面和 API 共同使用的服务端认证边界。
- 让锁定、禁用和会话撤销在多实例部署下保持一致。
- 为后续授权能力提供稳定的用户标识，不预先耦合具体角色模型。
- 使认证关键路径能够通过自动化测试验证。

**Non-Goals:**

- 本次不实现岗位、菜单、按钮或数据范围授权。
- 本次不实现用户自助注册、找回密码、多因素认证或单点登录。
- 本次不提供完整账号管理界面；初始化管理员与解锁由部署/管理流程承担，后续 P1-02 再提供正式管理能力。
- 本次不记录完整业务操作日志，避免抢占 P1-05 范围。

## Decisions

### 1. 使用服务端不透明会话而非浏览器持有 JWT

FastAPI 登录成功后生成高熵随机会话标识，只通过 `Secure`、`HttpOnly`、`SameSite=Lax` Cookie 下发。Redis 保存会话运行态与 30 分钟滑动空闲期限；每次受保护请求先验证会话，再加载 MySQL 中的用户启用/锁定状态。退出时删除服务端会话并清除 Cookie。

选择该方案是因为它能立即撤销会话、自然支持空闲超时，也避免长期令牌暴露给前端脚本。备选 JWT 虽减少服务端状态，但撤销、锁定即时生效和滑动超时需要额外黑名单机制，复杂度更高。

### 2. MySQL 保存账号安全事实，Redis 只保存运行态

MySQL 用户表保存规范化账号、密码哈希、启用状态、锁定状态、连续失败次数及必要时间戳，并通过事务与行级更新保证第 5 次失败只触发一次锁定。Redis 不作为账号启用或锁定状态的唯一来源；Redis 丢失最多导致现有会话失效，不得解锁账号或改变账号状态。

此选择遵循目标架构“正式业务事实存 MySQL”的约束。把失败计数仅放 Redis 虽写入更快，但缓存丢失会重置安全状态，因此不采用。

### 3. 密码采用 Argon2id 单向哈希

密码只保存带独立随机盐的 Argon2id 哈希，登录时使用恒定路径的安全验证函数。不存在账号也执行等价成本的伪哈希验证，并统一返回“用户名或密码错误”，降低账号枚举和时间侧信道风险。

备选 bcrypt 生态成熟，但 Argon2id 提供更强的内存成本控制，适合新系统。参数通过配置固定并允许后续逐步升级。

### 4. 前后端实施双层保护

Vue 路由守卫在进入业务路由前查询当前会话，失败则跳转登录页；FastAPI 的认证依赖是最终安全边界，所有业务路由默认要求有效会话。前端对认证失效响应统一清空本地用户快照并跳转登录页。受保护页面使用禁止缓存策略，避免退出后浏览器回退展示旧敏感内容。

仅依赖前端守卫无法阻止直接 API 调用，仅依赖后端会造成较差的页面体验，因此必须双层实施。

### 5. 会话安全与请求伪造防护

修改状态的请求除 SameSite Cookie 外还须通过 CSRF 防护；登录接口采用来源校验与限速，认证响应使用通用错误信息。Cookie 在生产环境只经 HTTPS 传输，开发环境通过显式配置使用安全的本地替代设置，不自动放宽生产策略。

## Risks / Trade-offs

- [Redis 不可用会阻断登录和受保护访问] → 健康检查暴露依赖状态，失败时安全关闭而不是绕过认证，并准备清晰的运维告警。
- [滑动超时导致每次请求写 Redis] → 仅在剩余期限低于刷新阈值时续期，同时保证外部行为仍符合 30 分钟空闲超时。
- [数据库事务竞争影响同一账号的高频失败请求] → 对登录端点按来源和账号键限速，并以数据库原子更新作为最终一致性保障。
- [仅实现认证可能被误认为已实现授权] → 后端路由只暴露认证主体，不赋予系统管理员隐式业务权限；角色和数据范围在后续变更单独实现。
- [浏览器回退仍可能短暂显示内存快照] → 受保护页面禁止缓存，并在应用恢复与路由切换时重新确认会话。

## Migration Plan

1. 建立前后端工程骨架与本地 MySQL、Redis 配置，先运行数据库迁移。
2. 通过受控初始化命令创建首个系统管理员账号，禁止内置固定密码。
3. 部署认证 API 和登录页，以健康检查确认数据库与 Redis 均可用。
4. 执行登录、锁定、禁用、超时、退出和未认证访问验收测试后再开放环境。
5. 回滚时先停止流量，再回退应用版本；新增账号表保留不删除，Redis 会话可整体失效以保证安全。
